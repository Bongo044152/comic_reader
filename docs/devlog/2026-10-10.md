## 後端

- 專案設定使用 ESM（`"type": "module"`），`tsc` 編譯到 `dist/` 後再用 Node 執行。多了編譯這一步，所以不需要 nodemon，也不需要 `.mjs`。
- Docker：把 `app/` 複製進 image，以 `USER node`（uid 1000）執行。除錯工具（如 curl）需要時再用 `exec -u root` 臨時安裝，不放進 image。
- log 預期的做法：寫到 stdout，格式用 JSON（pino），由 Docker 收集並設定 rotation（`max-size`、`max-file`）；過濾用 `docker compose logs | jq`，簡單條件用 `grep`。

## 決策

### 關於 V1 範圍

- V1 不做：閱讀紀錄（記住讀到哪一話）、個人設定、快捷鍵、暖色濾鏡、排程更新、自動閱讀、深色／淺色主題、手機版。
- 原因：這些功能的細節（寫入時機、設定怎麼儲存、介面）現在下不出決定，先讓一條主流程跑通，MVP 之後再看。

### 關於 API 的錯誤格式

- 錯誤碼與錯誤的回應格式先不定，目前只用 HTTP 狀態碼加三類錯誤（使用者端、來源端、伺服器）。
- 原因：還在紙上談兵，等實作時看需求再決定。

### 關於設定檔

- 各項上限（章節圖片的空間、同步的最短間隔）寫在設定檔，可以透過 Backend Management 修改，也可以直接編輯。

### 關於資料

- 資料依特性分兩種方式管理：metadata 放資料庫，圖片放檔案系統。資料庫裡再分成使用者相關與漫畫資料（共用）兩類，詳見 [data.md](/docs/requirement/data.md)。

## 困難

- Markdown 標題的錨點，在 VS Code 與 GitHub 對標點的處理不同（VS Code 會保留半形冒號，GitHub 會去掉）。標題的草稿標記因此用「草稿 」加空格，不含任何標點，兩邊算出來的錨點才一致。
