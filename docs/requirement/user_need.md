# Suwayomi 使用者需求（User Needs）

# 背景

「接案社」是由東華資工系成立的接案子社團

導師希望成員們（包括我也是成員）可以練習如何從頭開始建立一個新的專案，並且和其他人協同開發。

Suwayomi 是 github 上有名的漫畫閱讀器，他基於前後端的架構 + 插件（plugin）的方式管理組成。

其中後端透過 plugin 取得並儲存漫畫資源，前端負責使用者互動介面，plugin 則是針對特定網站的網路爬蟲。

---

需要搞清楚我們希望這個「基於網頁前後端」的漫畫閱讀系統，要提供哪些功能？

# 系統草稿（還沒有考慮 User Need）

> 補充：具體的系統功能，請參考 [frontend.md](frontend.md) 的總覽。

本系統預計分為三個主要模塊：前端、後端、plugin。
預計流程：前端向後端獲取漫畫資源，此時有兩種狀況：
    1. 後端沒有這個漫畫資源：透過 plugin 向特定網站獲取漫畫資訊，後端快取。
    2. 後端有這個漫畫資源：從快取中取出。

前端：呈現漫畫給使用者
    + 使用者登入（沒有註冊）
    + 主頁
    + 搜尋功能
    + 漫畫閱讀界面
    + 分類：使用者可以分類漫畫
後端：管理使用者、快取漫畫
    + 提供漫畫與漫畫資訊
    + 支援前端的功能
    + 與 plugin 互動
plugin：網路爬蟲，向某特定網站獲取漫畫資訊
    + 漫畫資訊：向特定的網站獲取漫畫資訊

# User Need

> UN 表示 User Need，每條依下列格式撰寫：
>
> - 作為一個：誰
> - 我希望：需求本身，不寫做法
> - 以便：動機或價值
> - 可能做法：候選方案，之後再討論取捨

## UN-1

作為一個：注重閱讀體驗的使用者

我希望：能依照自己的習慣和作品類型選擇閱讀方式

以便：條漫、日漫等不同排版的作品都能舒適閱讀

可能做法：

- 支援上下滑動閱讀
- 支援翻動閱讀
- 支援自動閱讀

## UN-2

作為一個：電腦用戶

我希望：可以善用滑鼠和鍵盤

以便：不用頻繁點擊畫面上的按鈕也能流暢操作

可能做法：支援常用快捷鍵（hot key）

## UN-3

作為一個：喜歡晚上熬夜看漫畫的讀者

我希望：晚上閱讀時畫面不會太刺眼

以便：長時間夜讀眼睛不容易疲勞

可能做法：提供護眼模式，可依需求選擇開啟或不開啟

## UN-4

作為一個：漫畫讀者

我希望：系統記住我讀到哪一話

以便：下次打開時可以直接接續

可能做法：標注我之前看到那一話

## UN-5

作為一個：追連載的讀者

我希望：有新的一話時系統能自己抓到

以便：不錯過更新，也不用逐部手動檢查

可能做法：可以手動更新或者背景自動更新漫畫

## UN-6

作為一個：會依環境調整介面的使用者

我希望：可以切換深色或淺色介面

以便：白天和晚上都能用舒服的介面

可能做法：提供深色／淺色主題切換

> 備註：UN-6 是可選需求

## UN-7

作為一個：等待漫畫載入的讀者

我希望：載入時知道系統正在處理

以便：不會誤以為當機而重複點擊或離開

可能做法：顯示載入動畫

## UN-8

作為一個：遇到系統錯誤的使用者

我希望：後端發生錯誤時（例如加載新的漫畫失敗），能在畫面上看到提示

以便：知道操作沒有成功，可以重試或改用其他方式

可能做法：在前端顯示紅色的錯誤提示

> 備註：UN-8 是潛在需求

## UN-9

作為一個：開到不存在頁面的使用者（例如網址打錯、漫畫已被移除）

我希望：知道這個頁面不存在

以便：不會面對空白畫面，並能回到主頁

可能做法：提供 404 頁面，附回到主頁的連結

> 備註：UN-9 是潛在需求

# 衝突

兩個需求或決策互相牽制，必須取捨。

| ID | 問題 | 相關 | 選項 | 狀態 |
| --- | --- | --- | --- | --- |
| C-1 | 資料夾與漫畫：同一部漫畫能否放進多個資料夾？資料夾存漫畫本身還是只存關係？ | A-5 | 已選：多對多，資料夾只存關係 | 已決定 |

| C-3 | 多人資料歸屬：哪些資料全體共用、哪些屬於個別使用者？ | A-1、UN-4 | 已選：直接做多人（見 A-1）。漫畫資料與快取以漫畫 id 共用，支援強制刷新；閱讀紀錄、資料夾、設定屬於使用者，細節開發階段釐清 | 已決定 |
| C-4 | 自動更新 vs 來源網站限制：背景檢查太頻繁可能被網站封鎖或擋下（如 Cloudflare） | UN-5 | 已選：限制最短間隔，對象為手動檢查更新與排程檢查更新 | 已決定 |
| C-5 | 閱讀紀錄 vs 來源章節變動：來源重新編號、刪除章節或換源後，「讀到哪一話」要指向哪裡？ | UN-4、C-2 | 已選：更新若會影響閱讀紀錄（重新編號、刪除章節、換源），系統不自動更新，交由使用者決定。選擇更新 → 系統不維護該部漫畫的閱讀紀錄 | 已決定 |
| C-6 | 圖片全部儲存 vs 硬碟空間：多人、多部漫畫累積下來，空間會持續增加 | A-8 | 已選：後台可設定空間上限，上限針對漫畫儲存而非個別使用者；空間不足時前端需顯示提示 | 已決定 |
| C-7 | 刪除漫畫：使用者移除書庫中的漫畫時，共用的漫畫資料、資料夾關係與閱讀紀錄怎麼處理？ | C-1、C-3 | 已選：只移除使用者自己的書庫關係，共用資料以 ref count 管理（歸零才回收） | 已決定 |

> 補充：書庫是每位使用者的預設資料夾，定義見 [data.md](data.md) 的 Folder。

| A-9 | 閱讀紀錄的粒度：記到哪一話，還是記到該話第幾頁？ | UN-4 | 已選：記到哪一話（見 UN-4） | 已決定 |
| A-10 | 護眼模式的定義 | UN-3 | 已選：暖色濾鏡（深色／淺色主題另列 UN-6） | 已決定 |
| A-11 | 使用裝置：只考慮電腦，還是手機也要能用？ | UN-2 | 已選：第一版先做電腦，之後再做手機 | 已決定 |
| A-12 | 加入新漫畫的入口：使用者要從哪裡發現並加入新漫畫？ | A-6、A-4 | 已選：本地搜尋 + plugin 搜尋（兩者都做）。plugin 搜尋由使用者勾選要搜的 plugin，勾全部即「全域」。備註：plugin 也需要同步更新 | 已決定 |
| A-13 | 帳號怎麼來：開放註冊還是管理者建立？需要管理者角色嗎？ | A-1、A-14 | 已選：第一版由後台（管理者）發配帳號 | 已決定 |
